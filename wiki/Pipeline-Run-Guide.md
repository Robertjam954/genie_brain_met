# Pipeline Run Guide

Step-by-step instructions for running the full analysis pipeline from raw data to
manuscript outputs. Run each stage in order; do not skip steps.

> Several scripts reference machine-specific absolute paths. Edit those paths for your
> machine before running. See [Getting Started](Getting-Started.md) for data setup.

---

## Stage 1 - Raw pull (R)

Reads raw cBioPortal / GENIE / GDC exports and HUGO gene annotations, emits a
consolidated workbook.

```zsh
Rscript "src/data collection and processing/pull_genie_data.R"
```

**Inputs:**
- Private cBioPortal study folders (adjust absolute paths inside the script)
- `data/hugo_symbols.xlsx`

**Outputs:**
- `data/extracted_variables_of_interest.xlsx`

> `extract_variables_of_interest.R` is a near-duplicate of this script. Either can be
> used; they are not both required.

---

## Stage 2 - Harmonize to canonical schema (Python)

One script per cohort. Each reads intermediate master CSVs from `data/processed/` (produced
upstream, partly in R / `gnomeR`, and not generated by any script in this repo), aggregates
the mutation MAF to a per-sample summary, recodes clinical variables, derives the brain-met
cohort, and adds time-to-event columns.

Run all three:

```zsh
python "src/data collection and processing/harmonize_genie.py"
python "src/data collection and processing/harmonize_tcga.py"
python "src/data collection and processing/harmonize_breast_msk_2018.py"
```

**Inputs (per cohort, from `data/processed/`):**
- `genie_bpc_v1_sample_master_full.csv`, `genie_bpc_v1_mutations.csv` (GENIE)
- Equivalent cBioPortal / GDC sources (TCGA, MSK)

**Outputs (written to `src/exploratory data analysis/`):**
- `extracted_variables_<cohort>_data.csv` - main analytic frame
- `extracted_variables_<cohort>_top_genes.txt` - top-mutated gene list
- `extracted_variables_<cohort>_gene_prev_brain_met.csv` - per-gene prevalences
- `extracted_variables_<cohort>_dictionary.csv` - variable recoding dictionary

---

## Stage 3 - Enrich (Python)

Rewrites the three analytic CSVs in place, adding:
- Long-form alias columns for key clinical variables
- Competing-event time-to-event columns needed for Aim 2
- GENIE-only: regimen-derived treatment flags (reads `data/processed/genie_bpc_v1_regimens.csv`)

```zsh
python "src/data collection and processing/enrich_harmonized.py"
```

**Inputs:** the three `extracted_variables_<cohort>_data.csv` from Stage 2, plus
`data/processed/genie_bpc_v1_regimens.csv` for GENIE.

**Outputs:** same files, rewritten in place.

> `add_pathways_genie_bpc.R` is the upstream R step that builds the GENIE gene-binary
> matrix and the 10 Sanchez-Vega `pathway_*` columns (gnomeR; `harmonization_spec.md`
> sections 13-14) and writes `data/processed/genie_bpc_v1_sample_master_full.csv`. Run it
> before Stage 2 if that master does not already carry the `pathway_*` columns that
> `harmonize_genie.py` expects.

---

## Stage 4 - Stage analytic frames for modeling (manual)

`_lib.load_cohort()` reads from `data/processed/`, but the harmonize scripts write to
`src/exploratory data analysis/`. Copy or symlink the files:

```zsh
mkdir -p data/processed

cp "src/exploratory data analysis/extracted_variables_genie_data.csv"           data/processed/
cp "src/exploratory data analysis/extracted_variables_genie_top_genes.txt"      data/processed/
cp "src/exploratory data analysis/extracted_variables_tcga_data.csv"            data/processed/
cp "src/exploratory data analysis/extracted_variables_tcga_top_genes.txt"       data/processed/
cp "src/exploratory data analysis/extracted_variables_breast_msk_2018_data.csv" data/processed/
cp "src/exploratory data analysis/extracted_variables_breast_msk_2018_top_genes.txt" data/processed/
```

---

## Stage 5 - Aim 1: Association analysis (Python)

Most scripts accept `--cohort {genie,tcga,msk18,all}`.

```zsh
# Gene/pathway prevalence tables, forest plots, oncoprints
python "src/exploratory data analysis/gene_prevtable_oncoprint_forest.py" --cohort genie

# Top-10 gene p/q table
python "src/exploratory data analysis/aim1_top10_pq_table.py" --cohort genie

# Univariate and multivariate logistic regression tables
python "src/exploratory data analysis/univariate and multivariate regression df and tables.py" --cohort genie
```

**Outputs:**
- CSV result tables: `src/modeling/<cohort>/aim1/`
- Figures/PDFs: `manuscript components/<cohort>/aim1/`

Repeat with `--cohort tcga` and `--cohort msk18` for the replication cohorts.

---

## Stage 6 - Aim 2: Time to brain metastasis (Python)

Restricted to the no-CNS-at-diagnosis cohort.

```zsh
python "src/modeling/proportional_hazard_afttest.py" --cohort genie
```

Runs KM + log-rank, Cox PH with scaled Schoenfeld diagnostics, and AFT distribution
selection (Weibull / lognormal / log-logistic by AIC).

**Outputs:**
- `src/modeling/<cohort>/aim2/` (CSV tables)
- `manuscript components/<cohort>/aim2/` (figures)

---

## Stage 7 - Aim 3: Overall survival (Python)

Restricted to the brain-mets-ever cohort. Requires >= 25 events (`MIN_EVENTS` guard).

```zsh
python "src/modeling/aim3_os.py" --cohort genie
```

Same KM / Cox PH / AFT machinery as Aim 2.

**Outputs:**
- `src/modeling/<cohort>/aim3/` (CSV tables)
- `manuscript components/<cohort>/aim3/` (figures)

---

## Stage 8 - ML survival benchmark (Python + R)

XGBoost-AFT survival model, concordance-index evaluation, SHAP feature importance.

```zsh
# Feature construction, training, and evaluation
python "src/modeling/xgb_aft_preprocessing_feature_constuction_train_validate_evaluate.py"

# Feature importance
python "src/modeling/xgb_aft_feature_.processing_feature_processing_feature_importance.py"

# SHAP analysis (Python)
python "src/modeling/xgb_aft_shap_feature_importance.py"

# SHAP plots (R)
Rscript "src/modeling/shap analysis and plot generation.R"
```

**Outputs:** `reports/figures/ml_benchmark/`

> The `src/modeling/README_survival_AFT_pipeline.md` describes a standalone
> `survival_and_xgb_analysis.py` CLI that does **not** match the current `_lib`-based
> layout. Treat it as a reference for an older variant; reconcile before relying on it.

---

## Validating outputs

There is no automated test suite. After each stage, validate by:

1. Checking printed diagnostics and row/event counts on stdout
2. Confirming output CSVs have expected row counts and no empty columns
3. Inspecting rendered figures for plausible KM curves, forest plots, and concordance values
