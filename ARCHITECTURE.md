# Architecture

This project is a clinical-genomics research pipeline that studies breast-cancer brain
metastasis in the GENIE BPC BRCA cohort (`genie`). It is organized as a linear
data-engineering and statistical-modeling pipeline rather than a deployed service: the raw
public GENIE BPC breast-cancer export is pulled, prepared into a single analytic frame, then
run through descriptive, regression, survival, and machine-learning analyses whose outputs
feed a manuscript.

> This document describes pipeline **structure** (inputs, outputs, and control flow). It
> does not assert any scientific result. The narrative results in the repo are unverified
> and pending author review.

## High-level flow

```
raw GENIE BPC cBioPortal export
  -> pull / extract        (R)   -> data/extracted_variables_of_interest.xlsx
  -> (upstream masters)          -> data/processed/*.csv   (partly gnomeR/R; not scripted here)
  -> build analytic frame  (Python) -> src/exploratory data analysis/extracted_variables_genie_*.csv
  -> enrich                (Python) -> same CSVs rewritten in place
  -> analytic CSVs read by modeling from   data/processed/extracted_variables_genie_data.csv
  -> Aim 1 / 2 / 3 analyses (Python)
  -> tables + figures      src/modeling/genie/aimN/, manuscript components/genie/aimN/
```

**Important location nuance.** The data-prep script *writes* its
`extracted_variables_genie_*` outputs into `src/exploratory data analysis/`, but
`_lib.load_cohort()` *reads* `extracted_variables_genie_data.csv` from `data/processed/`.
Those two locations differ, and `data/processed/` is not present in this repo, so the
analytic frame has to be placed under `data/processed/` before the modeling stage can
find it. Do not assume the ETL has been run end-to-end in this checkout.

## Main components

### 1. Data collection and processing (`src/data collection and processing/`)
- `pull_genie_data.R` - reads the raw GENIE BPC study folders from a local private data
  root, joins HUGO gene annotations (`data/hugo_symbols.xlsx`), and emits
  `data/extracted_variables_of_interest.xlsx`. `extract_variables_of_interest.R` is a
  near-duplicate of this script.
- `harmonize_genie.py` - the GENIE data-prep step. It reads intermediate master CSVs from
  `data/processed/` (e.g. `genie_bpc_v1_sample_master_full.csv`,
  `genie_bpc_v1_mutations.csv`), aggregates the mutation MAF to a per-sample summary
  (non-silent filter, mutation counts, alt-count max), recodes clinical variables, defines
  the brain-met cohort, derives top-mutated genes, and adds time-to-event columns. It writes
  four files - `extracted_variables_genie_data.csv`, `_top_genes.txt`,
  `_gene_prev_brain_met.csv`, `_dictionary.csv` - into `src/exploratory data analysis/`.
  The `data/processed/` master inputs are produced upstream (partly in R / `gnomeR`) and are
  **not** generated by any script in this repo.
- `harmonization_spec.md` - the analytic-schema contract: one row per `SAMPLE_ID`, exact
  column names, source-column candidates, and recoding rules (race/ethnicity/grade/stage/
  receptor subtype, organ-specific metastasis flags, OS / PFS / time-to-brain-met endpoints,
  the brain-met cohort derivation, mutation aggregation, gnomeR gene-binary matrix, and the
  ten Sanchez-Vega pathway columns).
- `enrich_harmonized.py` - post-prep enrichment: rewrites
  `extracted_variables_genie_data.csv` in place, adding long-form alias columns,
  competing-event time-to-event columns for Aim 2, and regimen-derived treatment
  flags from `data/processed/genie_bpc_v1_regimens.csv`.
- `add_pathways_genie_bpc.R` - **empty 0-byte stub**; it does nothing. Pathway indicators
  come from the data-prep step / upstream masters, not this file.
- `missing_analysis_table.py` (takes `--cohort`; writes a missingness audit CSV + rendered
  table), `create_deidentified_dataset.R` (standalone, references offline Windows paths),
  and `date_handling_template.R` - supporting QC and de-identification.

### 2. Exploratory data analysis (`src/exploratory data analysis/`)
- `gene_prevtable_oncoprint_forest.py` - Aim 1 core: 2x2 gene/pathway prevalence between
  brain-met and non-brain-met groups, Fisher exact tests, prevalence ratios with
  log-normal CIs, forest plots, and oncoprints.
- `univariate and multivariate regression df and tables.py` - logistic regression of
  `any_brain_met` on top genes and pathways (statsmodels), with multiple-testing correction.
- `aim1_top10_pq_table.py`, R correlation/regression scripts, and the per-cohort
  `*_retrieved_data/` and `msk_retrieved_data/` extracted CSV caches.

### 3. Modeling (`src/modeling/`)
- `_lib.py` - shared backbone. Defines the GENIE `CohortSpec`, loads analytic CSVs from
  `data/processed/`, reads top-gene lists, builds output dirs, and `prep_covariates()` /
  `drop_low_variance()` for one-hot encoding and small-cohort safety.
- `proportional_hazard_afttest.py` - Aim 2: time to brain metastasis (no-CNS-at-dx cohort).
  KM + log-rank, Cox PH with scaled Schoenfeld diagnostics, and AFT distribution selection
  (Weibull / lognormal / log-logistic by AIC).
- `aim3_os.py` - Aim 3: overall survival in the brain-mets-ever cohort, same KM/Cox/AFT
  machinery with a minimum-events guard (`MIN_EVENTS = 25`).
- XGBoost AFT scripts (`xgb_aft_preprocessing_..._evaluate.py`,
  `xgb_aft_feature_..._importance.py`, `xgb_aft_shap_feature_importance.py`) and
  `stratifiedKM_CoxFG_feature_prep_AFT.py` - survival ML using XGBoost's Accelerated Failure
  Time objective, concordance-index evaluation, and SHAP-based feature importance.
  `shap analysis and plot generation.R` reproduces SHAP plots via `SHAPforxgboost`.
- `survival_and_xgb_analysis.ipynb` + `README_survival_AFT_pipeline.md` describe a combined
  KM / Cox / Fine-Gray / XGBoost-AFT run. Note the README documents a standalone
  `survival_and_xgb_analysis.py` CLI (plus a `requirements.txt` and column names such as
  `DFS_MONTHS` / `SUBTYPE` / `MANTIS_BIN` / `G__*`) that does not match the current repo
  layout or the canonical schema - it appears to describe an earlier/separate variant and
  should be reconciled with the actual notebook and `_lib`-based scripts.

### 4. Notebooks and reporting
- `notebooks/` - descriptive, OS, and time-to-brain-met plotting notebooks, retrieval /
  metadata recoding, and a Cox-vs-AFT diagnostic notebook, plus a dataset-metadata template.
  The notebooks hard-code a `PROJ` root under the author's iCloud `Documents` and read/write
  there, not into this repo (see `docs/plans/finish-project-run-notebooks-plan.md`).
- Generated CSV result tables: the Aim scripts write to `src/modeling/genie/aimN/` (via
  `_lib.ensure_dirs`). The only result tables currently committed live under
  `src/data reports/genie/aim1/` (top-10 gene p/q, univariate / multivariate logistic,
  pathway p/q, gene-vs-pathway comparison) - i.e. Aim 1 only; the Aim 2/3
  result CSVs are not present in the repo.
- `manuscript components/genie/aim1/` - publication PDFs for those GENIE Aim 1 tables.
- `reports/figures/` - rendered PNG figures organized as `aim1/`, `aim2/`, `aim3/`, and
  `ml_benchmark/`. These are the figures surfaced by `docs/results_dashboard.html`.
- `docs/`, `references/` - manuscript structure, revision plans, and source-paper PDFs.

## Data flow and contracts

The hinge of the architecture is the analytic frame that `_lib.load_cohort()` and
`load_top_genes()` read from `data/processed/extracted_variables_genie_data.csv` plus
`extracted_variables_genie_top_genes.txt`. (As noted above, the data-prep step writes
these under `src/exploratory data analysis/`, so they must be copied into `data/processed/`;
that directory is absent in this checkout.) The analytic frame exposes standardized columns
(`any_brain_met`, `brain_met_at_dx`, `OS_months`, `os_status_bin`, `top5_any_mutated`,
`receptor_primary_cat`, `grade_ord`, the `pathway_*` set) that the Aim 1/2/3 scripts consume
via the `--cohort genie` key.

**Provisional-results caveat.** The repo's narrative results (dashboard, methods) are
unverified and may contain errors. This document intentionally does not restate any specific
numeric finding.

## Key technologies

- Python: pandas, numpy, lifelines (KM, Cox PH, Schoenfeld, AFT fitters, Fine-Gray),
  statsmodels, scipy, scikit-learn, xgboost (AFT objective), matplotlib, seaborn.
- R: tidyverse (dplyr, readr, tidyr, purrr, stringr), data.table, openxlsx, broom,
  lubridate, xgboost, SHAPforxgboost.
- Data source: GENIE BPC breast-cancer cBioPortal study export (MAF mutation files plus
  clinical tables).

## Candidate driver-gene workflow (reference)

`notebooks/Workflow_CBBio.pdf` (= `src/Workflow_CBBio.pdf`) documents the CBBio candidate
driver-gene fusion method (Leila Mirsadeghi): four driver callers (MutSigCV, OncodriveCLUST,
OncodriveFM, NetBox) rank genes by p-value, each contributes one `-log10(p)` feature per
gene, and an SVM/ANN/RF ensemble with an algebraic (average-score) combiner outputs the final
candidate-driver-gene set. Run notes are reproduced in `docs/CBBio_workflow.md`; the method
citations and caller-tool sources are in `references/REFERENCES.md` (§2-§3). This is reference
material - the caller tools and ensemble scripts are external prerequisites, not committed to
this repo.
